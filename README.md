# MoveSketch

> 캐주얼하게 조깅과 라이딩을 즐기는 사람들을 위한, 부담 없는 세션 트래킹 앱

MoveSketch는 경쟁과 기록 단축의 압박에서 벗어나, 운동 결과를 수치와 순위 대신 한 컷 이미지로 남기고 아카이빙합니다.

---

## 1. 목표 및 설계 철학

기존 러닝/라이딩 앱은 기록 경쟁과 순위 경쟁에 초점이 맞춰져 있어 일상적인 운동을 즐기는 사용자에게 진입 장벽과 피로감을 줍니다.
반면 단순 만보기 앱은 능동적인 운동 세션의 완결성을 담아내지 못합니다.
MoveSketch는 그 사이에서 '부담 없는 시작과 즐거운 기록'을 지향합니다.

- **명확한 세션 단위**: '시작'과 '완료'가 존재하는 온전한 운동 트래킹
- **결과 중심의 사후 보상**: 사전에 과도한 목표치를 강제하지 않고, 실제 운동 결과에 따라 사후 보상 지급
- **비교 없는 기록**: 타인과의 수치 경쟁 대신, 그날의 여정을 한 컷의 스케치 이미지로 축적

### 네 가지 핵심 원칙

| 원칙 | 실천 내용 |
| :--- | :--- |
| **비교하지 않는다** | 리더보드, 랭킹, 순위 비교 화면을 배제하고 친구 간에는 순수한 응원만 전달합니다. |
| **강요하지 않는다** | 미션은 최대 2개까지 선택하는 **부담 없는 참고용 제안**이며, 세션 도중 미달성을 지적하지 않습니다. |
| **실패를 규정하지 않는다** | 미션을 달성하지 못해도 세션 카드는 온전히 보존되며, 결과 화면은 부족한 수치를 강조하지 않습니다. |
| **프라이버시 기본값** | 소셜 공유 시 정밀 GPS 좌표와 상세 수치는 제외되며, 동네 단위 지역명과 스케치 이미지 중심의 안전한 공유를 지원합니다. |

## 2. 핵심 기능

### 2.1 축 기반 미션 시스템

세션 시작 전 수치 목표를 강제하지 않고, 오늘 가볍게 신경 쓸 미션 축을 최대 2개 선택합니다.

- **공통 축**: 거리, 지속시간, 페이스 및 속도
- **조깅 전용**: 인터벌
- **라이딩 전용**: 스프린트

세션 종료 후 도달한 성과 구간에 따라 스케치 파츠 에셋이 결정됩니다.

### 2.2 스케치 파츠 보상 및 이미지 합성
- **Zero-Intervention 자동 합성**: 사용자가 파츠 위치를 수동 조작할 필요 없이, 달성 성과에 맞춘 슬롯별 파츠가 자동으로 조화롭게 합성됩니다.
- **결과물 아카이빙**: Flutter의 `RepaintBoundary` 기반 캡처 파이프라인을 거쳐 무손실 이미지로 생성되며, 로컬 및 클라우드 스토리지에 보관됩니다.

### 2.3 지능형 자동 / 수동 일시정지
- **자동 일시정지**: 신호 대기 등으로 정지 시 GPS 속도 임계값을 감지하여 자동으로 타이머를 멈추고, 이동 재개 시 트래킹을 복구합니다.
- **수동 일시정지**: 화면의 일시정지 제어를 통해 진입하며, 경과 시간과 이동 거리를 확인한 뒤 세션 재개 또는 안전한 조기 종료를 선택할 수 있습니다.

### 2.4 오프라인 우선(Local-first) 저장 및 동기화
- **데이터 유실 방지**: 모든 세션 및 트래킹 포인트는 오프라인 상태에서도 기기 로컬 SQLite(Drift)에 즉시 저장됩니다.
- **동기화 상태 알림**: 오프라인 상태에서 완료된 미동기화 세션이 존재할 경우 홈 화면 상단에 배너가 표시되며, 원터치 수동 동기화를 지원합니다.
- **백그라운드 동기화**: 앱 재실행 또는 네트워크 연결 복구 시 백그라운드 UseCase가 이를 감지하여 원격 Firestore로 안전하게 동기화합니다.

### 2.5 소셜 피드 및 알림 생태계
- **스케치 소셜 피드**: 친구의 스케치 카드를 확인하고 따뜻한 응원과 댓글로 소통합니다.
- **관심 친구 푸시**: 특정 친구를 관심 친구로 설정하면 해당 친구가 새 스케치를 게시했을 때 즉시 알림을 받습니다.
- **운동 리마인더 알림**: 당일 운동 기록이 없는 사용자를 대상으로, 개인이 설정한 시간대에 맞춰 Cloud Functions 스케줄러 기반 리마인더 푸시를 발송합니다.

## 4. 아키텍처 및 기술 스택

### 4.1 소프트웨어 아키텍처
MoveSketch는 **[Flutter 공식 앱 아키텍처(Flutter App Architecture)](https://docs.flutter.dev/app-architecture)** 가이드라인을 지향하여,
레이어 간 관심사를 분리하고 단방향 데이터 흐름을 유지하도록 설계되었습니다.

```text
lib/
├── config/                # 앱 전역 설정, 환경 변수 및 상수
├── data/                  # 데이터 소스 및 Repository 구현체
│   ├── repositories/      # Domain Repository 인터페이스 구체 구현
│   └── services/          # 물리적/시스템적 데이터 I/O 서비스 (local, remote, hardware)
├── domain/                # 순수 비즈니스 로직 및 핵심 규칙
│   ├── models/            # 불변 데이터 모델 및 상태 머신
│   └── use_cases/          # 단일 책임 비즈니스 유스케이스
├── routing/               # 선언형 화면 라우팅 및 딥링크 설정
├── ui/                    # Feature-first 기반 MVVM 프레젠테이션 레이어
│   ├── core/              # 전역 디자인 시스템, 공통 테마 및 재사용 위젯
│   └── <feature>/         # 기능별 화면 모듈 (home, session, feed, history 등)
│       ├── view_models/   # Riverpod 상태 관리 (AsyncNotifier / Notifier)
│       └── widgets/       # 화면 및 종속적 UI 컴포넌트
├── utils/                 # 순수 유틸리티 (포맷터, 날씨 헬퍼, 계산식 등)
└── main.dart              # 앱 진입점 및 전역 인프라/상태(ProviderScope) 초기ㄹ화
```

### 4.2 주요 기술 스택

| 영역 | 도입 기술 | 채택 배경 및 비고 |
| :--- | :--- | :--- |
| **Framework** | Flutter (Dart 3.x) | 크로스 플랫폼(iOS, Android, Web) 단일 코드베이스 유지 |
| **State Management** | Riverpod 2.x | 컴파일 타임 안정성, 의존성 주입 및 반응형 상태 관리 |
| **Local Storage** | Drift (SQLite) | 오프라인 우선 세션 저장 및 타입 안정적 쿼리 |
| **Cloud Backend** | Firebase | Auth, Firestore, Cloud Storage |
| **Serverless Engine**| Cloud Functions (Node.js 24) | TypeScript 기반 알림 디스패처 및 24시간 리마인더 스케줄러 |
| **Location & Map** | Geolocator, flutter_map | 고정밀 백그라운드 위치 수집 및 OpenStreetMap 기반 경로 렌더링 |
| **Graphic Pipeline** | RepaintBoundary | 파츠 레이어의 손실 없는 PNG 합성 |
